## The reason to buy

Choose what matters today, reserve time in the week, settle into a quiet workspace and keep a readable record of the session. One purchase would include the accepted desktop package and its bundled content. Price and Steam eligibility remain undecided. No account, advertisement, subscription, content unlock or network call is needed during the planned core routine.

The useful difference to test is planning that leads directly into focus. Someone who already uses a calendar, a task list and a timer should be able to take a real deadline through one routine with less repeated entry. Test that with the silent workflow trial before spending time on presentation. The Steam comparison includes both paid and free alternatives.

The paid-value hypothesis has four parts: see a real deadline beside available time; start focus on the chosen task without entering its name again; keep a small readable timer beside other work; return to useful local records with a calm, consistent presentation. Offline use, recovery and no advertising strengthen this package. They do not alone prove that someone will buy it.

Use one short promise for a demonstration: **Plan today's work, focus on the chosen task, and return to a clear record.** Test the whole routine against the participant's current tools. Do not expand the feature list to compensate for weak repeat use.

## A complete first routine

1. Choose local saving or temporary use. The explanation says exactly what survives closing.
2. Capture or select a task such as "Draft the report". Add Friday's deadline and a short note only if useful.
3. Start a 25-minute, 50-minute or custom countdown directly from that task. Carry its title into focus without another title form. No deadline, pin, calendar block or music selection is required.
4. When useful, reserve a separate writing block in Week or pin the existing task in Today. Moving the block leaves the deadline unchanged. Music stays optional and starts only by explicit choice.
5. Switch the same app window to its compact timer view while writing. Pause, resume or end the session explicitly.
6. Review recorded timer time. Decide separately whether the task is complete, then choose a break or stop.
7. Return tomorrow to saved plans. Export a private backup when needed.

The scene or player can fail without losing the task or blocking Save. Wallpaper integration is later work.

Start focus directly from a task. Use Week when the person needs to reserve time. Follow the [report demonstration](REDESIGN.md#planning-to-focus-design-review) to show the deadline, work block and timer record without adding setup steps to the focus action.

## Proposed interaction contracts

These contracts make the target reviewable. The learner must explain and test them in the relevant lesson before implementation. They do not silently replace the existing application or data specifications.

### Planning and saving

A task deadline and a work block are separate records. A task may have no date. An empty calendar interval means nothing is recorded, not that the person is free. Use one workspace, one timezone and one active writer. Show the effective date and time clearly. Reject unsupported recurrence patterns instead of approximating them.

Editors use explicit Save. Only a confirmed write shows Saved. A failed write retains the input and offers retry. Closing a dirty editor offers Save, Discard or Cancel. A completed timer never completes a task. Deleting a task must not erase its prior timer record; retain a plain historical label without a live task link.

Local mode stores accepted records on the device. Temporary mode does not open old private data or create recoverable automatic copies. Its exit warning and explicit export must be clear. Local database and JSON exports are initially unencrypted. Do not label them encrypted or secure vaults.

Backups include versioned planning records, accepted sessions and user preferences. They refer to bundled media by stable identifiers, not copied audio files. Restore validates the whole input, shows counts and replacement scope, then replaces atomically. An invalid, cancelled or failed restore leaves the current workspace intact. Unsupported future versions are rejected with a clear message.

### Timing and lifecycle

Use one shared timer state: idle, running, paused, break or awaiting review. Focus and break use the same countdown rules. Manual choices start the next interval; no automatic multi-round cycle is required. Countdown completion produces one event, even if duplicate callbacks arrive. Record focus time separately from break time. A session may keep a task reference and historical title, but task completion remains a separate action.

Use elapsed time that is not changed by editing the wall clock. The proposed sleep policy pauses focus when the device suspends. Resume asks the person to continue; it does not credit unknown time. A restart marks the prior session interrupted. Only the last confirmed elapsed checkpoint may be offered for review. It must never invent the closed-app interval.

Local mode may checkpoint the running session at bounded intervals. Temporary mode keeps it only in memory. A checkpoint failure leaves the timer visible but marks the record unsaved. Retry uses the same session identifier to avoid duplicates. Detailed checkpoint interval and retention bounds belong to the learner's persistence lesson.

Minimize keeps the timer running while the process is alive. Explicit Exit stops playback and offers to finish or discard an active session. Window close must not silently become an invisible background service. Compact mode changes the layout and size of the same window; it does not start another timer or player. Resolve a dirty editor before switching modes. Restore the normal layout and clear any compact-only always-on-top choice when returning to the planner. Closed-app alarms and guaranteed Windows notification delivery are excluded.

### Sound and scenes

Sound starts only after an explicit play choice. A fresh launch stays silent. Remember track, levels and theme only under the chosen saving policy. Notification cues have a separate mute switch. Audio fades prevent sharp starts and stops; a quiet cue must not jump above the music. Do not change system-wide volume.

The music player works independently of the timer. Audio device removal pauses playback and shows a retry choice. Missing files, decode errors and device changes do not pause a timer or discard edits. Read bundled files locally; do not fetch codecs, songs, artwork or analytics during use. Publish the supported packaged audio format only after testing the actual Windows decoder.

The prepared music has finished tails. It is **not** certified for seamless looping. First release uses a short fade-out/fade-in for repeat or track changes; overlapping crossfades are not required. Scene animation and ambient layers are deferred. The plain focus surface retains every control. Hide large artwork while editing if it competes with readable text.

### Optional Wallpaper Engine controls

This is a post-launch experiment, not first-release work or a marketing claim. Cadence must work fully without it. If selected later, begin with one opt-in action from the documented local interface and the user's own installed copy. Use a bounded timeout and show failures. Do not execute arbitrary user-supplied shell commands or bundle someone else's wallpaper. Preserve later manual wallpaper changes; only promise restoration after that case is tested.

## Quality targets

These are candidate budgets, not measurements. Record the test machine, build, resolution and workload with each result. Revisit them after the first packaged implementation.

| Area | Proposed target and check |
|---|---|
| Startup | Useful saved Today view within three seconds on the chosen reference Windows laptop after a warm launch |
| Background use | Average idle process CPU below 1% of total machine capacity over five minutes with motion off; report spikes separately |
| Memory | Working set below 250 MiB in the plain planner and 400 MiB during bundled music plus a static scene |
| Distribution | Runtime media below 45 MB and installer below 150 MB as initial budgets; editable masters are not shipped |
| Audio | No clipping, abrupt cue peaks or audible end clicks; consistent perceived levels; 30-minute sequential playback/repeat review on headphones and speakers |
| Access | Full routine by keyboard; visible focus; 200% text; screen-reader labels; Japanese, English and Chinese review |
| Offline | After legitimate acquisition and installation, complete planning, focus, playback, export, restart and restore without a network |
| Recovery | Interrupted write, full disk, corrupt backup, wrong version, cancelled dialog and second-writer cases preserve confirmed data |

Steam acquisition, updates and initial platform setup can require a network. Do not turn a tested offline runtime claim into a claim that purchase or installation works offline. Do not silently enable Steam Cloud for private planner data.
