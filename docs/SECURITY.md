# 安全与数据保护设计

更新：2026-11-10。状态：目标设计，尚未实现或通过安全验收。范围为桌面本地规划、候选 Web 系统和未来获准的学校连接。当前 `website/` 是静态介绍页，仅使用虚构演示数据；它不是学生课表系统。手机应用不在产品计划中。

## 保护什么，防范什么

| 数据 | 风险与边界 |
|------|------------|
| 课程、教室、日期与个人安排 | 能暴露行动规律，按私人数据处理；公开课程目录不等于个人课表可公开 |
| 作业、备注、完成情况、完整备份 | 仅用户主动选择的本地用途；不混入课表分享、日志或公开问题报告 |
| 学校身份标识、会话、令牌 | 最小范围、最短必要保留；密码不收集，凭据不进入普通数据库导出 |
| 运行诊断与支持信息 | 默认只需版本、系统、错误类别和脱敏复现步骤；用户预览后主动提交 |
| 官网语言选择与托管请求记录 | 与应用数据分开说明；当前官网没有账号、课表上传或分析脚本 |

主要威胁包括共享电脑上的数据暴露、误分享备份、不可信导入、脚本注入、跨用户越权、会话泄漏、存储清理造成丢失及供应链变更。核心离线可用不等于数据已加密；本设计不声称能防御已完全受控的操作系统或浏览器。

## 桌面与所有客户端的基线

- 仅在应用私有用户目录保存数据库与草稿，使用正常用户权限；不存入仓库、安装目录或自动公开共享目录。
- 当前没有实现数据库或备份加密，不得宣传“已加密”或“端到端加密”。发布前评估设备丢失场景；若引入加密，采用维护中的标准实现，独立评审密钥存储、恢复和迁移，禁止把密钥与数据明文一起保存。
- 私人数据默认不上传；课程分享采用字段白名单和实际内容预览，备份单独标明包含私人信息、是否加密及保存责任。
- 导入限大小、结构、版本、记录数与字段长度；课程名、备注和链接均为不可信输入，不执行 HTML、脚本、命令或导入文件指定的路径。禁止导入触发任意联网请求。
- 本地写入、迁移与恢复保留事务、版本校验和恢复备份；失败不清空原数据。草稿、临时文件和恢复副本也进入保留/清理说明。
- 提供数据位置、导出、删除与关闭通知内容展示的控制。删除说明必须涵盖副本和限制；不能保证撤回已经分享的文件，也不能承诺普通删除能物理擦除磁盘。
- 凭据若成为必要项，桌面使用经过验证的系统凭据存储；全量备份也不包含令牌。认证与课表权限按 [UNIVERSITY_INTEGRATION.md](UNIVERSITY_INTEGRATION.md) 分开确认。

## Web 候选方案与选择条件

| 候选 | 数据路径 | 上线前必须解决 |
|------|----------|----------------|
| 浏览器本地应用，静态托管 | 代码由托管方分发；学生数据只在自己的浏览器与主动导出的文件中 | 浏览器存储可靠性、共享设备、脚本供应链、导入导出、离线缓存和清除能力 |
| 必要时增加认证中间服务 | 用户与获准认证方交互，中间服务处理必要会话 | 学校许可、具体协议、会话保护、最小数据中转、运行责任和费用 |
| 服务端保存或跨设备同步 | 私人数据进入服务端 | 单独的需求决策、权限隔离、存储与密钥、删除/恢复、审计、成本和维护承诺 |

优先验证浏览器本地方案；存在真实需求时才评估其他方案。静态网页不能隐藏客户端密钥，也不能自行提供可信后端。学校的跨域限制不通过任意公开代理绕过。Flutter Web 与其他实现方式需验证可访问性、性能、存储和部署约束后再选择；当前没有 Web 应用工程。

### 浏览器本地数据

浏览器数据库（例如 IndexedDB）只是一种候选存储适配器，不等同于桌面 SQLite 文件，也不是安全保险箱。浏览器可能按配额或存储策略清除数据；即使获得持久存储许可，用户仍可清除站点数据。因此需要首次保存说明、导出备份、容量错误处理、恢复验证，并测试隐私模式、清理站点数据与多标签写入冲突。不能宣称永久保存。[MDN 存储配额与清理](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

共享电脑默认提供不持久保存的会话选项；用户明确选择后才留存私人数据，退出或清理时覆盖数据库、缓存及临时状态的实际范围。应用锁如无独立加密机制，不能描述为本地保密保障。

### 页面与部署边界

- 应用与宣传官网优先使用独立 origin，隔离脚本、存储与缓存；同域不同路径不构成存储隔离。
- 用户输入按文本渲染，必要富文本采用审查过的清洗机制。采用严格 CSP、HTTPS、限制第三方脚本与外部连接；验证托管平台能配置所需响应头。生产应用不默认沿用当前官网的托管配置。
- 不在 URL、静态构建资源、公开仓库、源映射、错误报告或分析事件中放入课表、学校身份和密钥。认证回调按协议即时消费并清理，避免泄漏到历史和访问日志。
- 不用 `localStorage` 或 `sessionStorage` 保存会话标识和长期令牌。浏览器中的脚本可读取同源可访问数据；将数据移入 IndexedDB 不会解决 XSS。需要服务端会话时按下一节设计。[OWASP HTML5 安全](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)
- Service Worker 只缓存明确允许的应用静态资源，不缓存认证回调和私人 API 响应；更新、回滚、断开连接和清除数据要测试。离线可用与关闭浏览器后的提醒分别验收。

### 仅当存在后端时的附加要求

- 所有私有接口逐请求验证身份、记录所有权和字段权限，默认拒绝；查询、导出、修改、删除与批量接口都不得信任客户端传入的用户 ID。测试两个账户互访、猜测 ID 和更改筛选条件。[OWASP 授权设计](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
- Web 会话采用适合获准协议的短期、可撤销机制。Cookie 会话设置 Secure、HttpOnly、合理 SameSite 与作用域；变更请求有 CSRF 防护，CORS 使用明确来源白名单。认证前后轮换会话、验证回调 state/nonce 或对应协议的防重放要求，限制登录和接口滥用。Cookie 标记不代替 XSS 防护。[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- TLS 保护传输；服务端密钥与数据库分离管理、权限最小化并轮换。私有响应禁止公共缓存；私有备份与日志有访问控制、保留期限、删除与恢复演练，不使用可公开猜测的下载地址。
- 账户退出、连接撤销、个人数据删除和备份到期的实际语义写入隐私说明。管理人员访问须有必要目的、最小权限和不含正文的审计记录。同步冲突及离线重试不能覆盖另一人的数据。
- 上线前确定维护者、故障/安全事件联系方式、学校通知路径（若适用）、关闭服务和数据导出方案；不许诺尚无资源支撑的响应时限。

## 安全验收与发布

| 阶段 | 必须提供的证据 |
|------|----------------|
| 桌面试用 | 分享字段检查、恶意/损坏文件拒绝、写入失败回滚、备份恢复、数据清理与脱敏问题报告 |
| Web 决策 | 架构和数据流、威胁评审、目标浏览器存储/清理/多标签验证、托管安全能力、运行成本与负责人 |
| Web 有限试用 | 输入注入、CSP/缓存检查、依赖检查、清除与恢复；若有后端，增加越权、CSRF、会话过期/撤销和限流验证 |
| 学校连接 | 有效许可、最小字段、凭据隔离、失效与撤销、部分失败、来源新鲜度与用户修改保护 |
| 全校推广 | 实际客户端验证、可联系维护者、升级/回滚/恢复演练、隐私告知及敏感缺陷的非公开报告方式 |

不得要求用户把真实密码、令牌、完整课表或备份贴到公开 issue。发现敏感泄漏时停止相关数据访问、处理凭据与发布版本、评估影响并按确定的流程通知。安全要求随实际实现补充测试；本次仅更新设计，不宣称已有任何后端或已通过这些检查。
