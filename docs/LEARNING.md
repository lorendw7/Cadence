## 分工

你写 `lib/` 中的功能代码；助手负责测试、解释、代码审阅，以及你明确交给助手的文档和官网维护。每次只讲一个小节，等你写完、检查通过后再继续。助手不会提前替你写下一节的实现。

每节按“一个目标 → 必要概念 → 你写代码 → 助手运行测试并解释失败 → 你修正”进行。测试不通过时先定位原因，不直接改测试来迁就错误实现。

## 技术栈：用到再学

| 技术 | 通俗解释 | 什么时候使用 |
|------|----------|----------------|
| Dart | 写数据、条件判断和计算的语言 | 第一节 |
| Flutter / Material 3 | 把数据画成跨平台窗口、按钮和列表 | 模型完成后 |
| Flutter 内置状态（setState） | 告诉当前界面数据变了，需要重画 | 最初的列表和表单 |
| Riverpod | 让多个页面共享同一份状态 | 页面开始共享数据时 |
| SQLite + drift | SQLite 把数据存在本地文件；drift 提供 Dart 访问方式 | 开始保存和重启恢复时 |
| 本地通知适配器 | 由操作系统显示提醒，候选 flutter_local_notifications | 持久化日程与权限处理完成后 |
| flutter_test | 自动检查功能结果和界面操作 | 助手编写；你逐渐学会读失败信息 |
| 纯 Dart + Flutter 条形展示 | 在本地计算并展示周回顾 | 核心日程和任务数据稳定后 |
| HTML / CSS / 少量 JavaScript | 现有静态官网，独立于桌面应用 | 当前由助手维护 |

继续使用仓库固定的 Flutter 3.44.4 / Dart 3.12.2，不为学习随意升级。Riverpod、drift 尚未安装，第一节不需要安装新包。官方资料：[Flutter 桌面](https://docs.flutter.dev/platform-integration/desktop)、[Riverpod](https://riverpod.dev/)、[drift](https://drift.simonbinder.eu/)。

## 教学顺序

每一行是阶段，不是一次课程；之后按需要继续拆成 20–45 分钟的小节。

1. 待办数据：类、字段、构造函数；再学习修改、校验。
2. 极简待办列表：显示、输入、添加、完成与撤销；内存数据阶段明确提示关闭会丢失。
3. 本地保存：数据库、重启恢复、可恢复编辑草稿和失败提示；再组织共享状态。
4. 今天与个人安排：每日待办计数、日期切换、起止时间、编辑与删除。
5. 周计划与课程：先单次课程，再学期、节次、单双周和单次调停课。
6. 任务截止、课程关联与考试。
7. 本地周回顾：先计划时长与重叠去重，再任务数量与上周对比。
8. 本地通知：先应用运行中的提醒，再单独验证后台能力。
9. 备份、课表分享、三语、桌面验证与分发。

这只是学习顺序调整，不取消产品要求。任意学校表格/截图识别不作为起步条件。固定模板 CSV / 粘贴课表属于后续候选增强，见 [QUICK_IMPORT.md](QUICK_IMPORT.md)。

## 时间预期

完整首版约 80–140 个开发工时，含基础本地统计、编辑草稿、每日计数和运行中通知，不含退出后提醒与候选 CSV 快速导入。它是开发估算，不是零基础学习时长。学习、练习和返工会增加时间；先完成前三小节，再按你的实际节奏估算日历进度。
