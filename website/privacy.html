DATA & PRIVACY

データを、どう扱うか。

現在の紹介サイトが扱うデータと、今後の Web 版に向けた設計要件を分けて説明します。日程管理の Web アプリは、まだ提供していません。

最終更新：2026年11月10日

01 — 現在の紹介サイト

表示言語の選択だけを cadence-lang というキーでブラウザーの localStorage に保存します。インタラクティブな例は架空のデータを使い、操作結果は保存しません。個人の日程、タスク、学校アカウントを入力・アップロードする機能はありません。

02 — Web 版の標準動作：未実装

今後の Web 版は、標準では予定とタスクを実行中のメモリー内だけで扱う設計です。再読み込みやタブ終了で未保存の内容が失われることを明示します。基本機能に学校ログインや登録を要求しない方針です。これらはまだ実装されていません。

03 — 任意の端末内保存：設計要件

明示的に本機への保存を有効にした場合だけ、ブラウザーの localStorage に書き込む計画です。暗号化された保存ではなく、同じブラウザーの利用者から見える可能性があります。共用端末では有効にしないこと、ブラウザーのデータ消去で失われることを案内します。この保存機能は未実装です。

04 — バックアップと削除：設計要件

JSON ファイルでの書き出しと読み込み、明示的なデータ削除を計画しています。JSON は個人情報を含む平文の完全バックアップで、匿名の時間割共有形式ではありません。ブラウザー内データの削除と書き出し済みファイルの削除は別であり、復元には事前のバックアップが必要であることを説明します。これらも未実装です。

05 — 通信と外部サービス

現在のサイトは GitHub Pages で配信し、ホスティング側では IP アドレスなどの基本的なリクエスト情報が記録される場合があります。外部の解析スクリプト、広告、リモートフォントは使っていません。将来の Web 版では予定やタスクをサーバーへ送信しない設計を基本とし、データの扱いが変わる場合は提供前に説明を更新します。

06 — 学校との関係

Cadence は学生や教員などが独立して使えるツールを目指すプロジェクトで、九州大学の公式サービスではありません。学校アカウントの認証情報を求める機能や学校システムとの同期はありません。将来の接続には正式な許可とデータ提供方法の確認が必要です。

07 — 問題を報告するとき

公開の GitHub Issue に個人の予定、学校のパスワード、認証情報や個人データのファイルを添付しないでください。ブラウザーと再現手順など、問題の説明に必要な情報だけを共有してください。
