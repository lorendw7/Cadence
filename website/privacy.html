DATA & PRIVACY

データを、どう扱うか。

現在の紹介サイトの動作と、開発中のローカルな時間管理ツールの設計を分けて説明します。学習用アプリのタスクはメモリー内のみで、日程管理や保存機能はまだ実装されていません。

最終更新：2026年11月12日

01 — 現在の紹介サイト

表示言語の選択だけを cadence-lang というキーでブラウザーの localStorage に保存します。架空のプレビューの操作結果は保存しません。個人の日程、タスクやアカウントを入力・アップロードする機能はありません。

02 — 初回に保存方法を選ぶ：設計

デスクトップ版では、初回に「この端末に保存」か「一時的に使う」を明示的に選ぶ設計です。どちらもアカウントは不要です。一時利用はメモリー内だけで、終了すると失われます。保存を選ぶ前に、予定・タスク・草稿を永続保存しません。これらの保存選択は未実装です。

03 — 端末内のデータ：設計

初版は、保存が完了した予定やタスクを端末内に置き、オフラインで使う計画です。端末内ファイルは暗号化しません。未保存の入力はメモリー内のみで、異常終了すると失われる場合があります。一時利用の内容は終了で失われます。これらの保存機能は未実装です。

04 — バックアップと削除：設計

JSON の書き出し、読み込み前の確認、明示的な削除を計画しています。JSON は個人の予定やタスクを含む平文のバックアップで、公開共有用ではありません。アプリ内データの削除で、書き出したファイルや他の人に渡したコピーは消えません。これらは未実装です。

05 — 通信と外部サービス

現在のサイトは GitHub Pages で配信し、ホスティング側で IP アドレスなどの基本的なリクエスト情報が記録される場合があります。外部の解析、広告、リモートフォントは使っていません。将来のローカルアプリは予定やタスクを送信せずに使える設計です。

06 — 接続を増やさない方針

外部の教務システムへの接続、学校ログイン、時間割の自動取得は現在の計画から外しました。Web 版やクラウド同期も開発対象に含めません。任意の AI 補助は別の将来研究であり、現在のサイトに送信機能はありません。再検討する場合も、送信先・内容・料金・保存規則を確認できる設計を先に定めます。

07 — 問題を報告するとき

公開の GitHub Issue に個人の予定、パスワード、認証情報や個人データのファイルを添付しないでください。ブラウザーや OS、再現手順など、問題の説明に必要な情報だけを共有してください。
