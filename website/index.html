02 / DATA PROTECTION BY DESIGN

残し方も、自分で決める。

以下は未実装の Web 版に向けた設計要件です。標準はセッション内だけとし、端末内保存やバックアップを自分で選べるようにします。

データの扱いを詳しく読む↗
  1. 1

    まずは、そのまま使う

    標準ではメモリー内だけで動作する計画です。再読み込みや終了で未保存の内容が失われることを、明確に案内します。

  2. 2

    自分の端末に保存する

    明示的に有効にした場合だけブラウザー内へ保存する設計です。暗号化はされないため、共用端末での利用には注意を示します。

  3. 3

    必要なときに書き出す

    JSON の書き出し・読み込みを計画しています。平文の個人データを含むことと、保存・共有時の注意を説明します。

03 / THE NEXT WORKING STEP

まずは、小さく確かな一歩を。

Web 版はこれからの開発方向です。初期設計では日程の作成・編集・削除、終わりのある毎週の繰り返し、タスク完了、JSON の書き出しと読み込みに絞ります。

現在、使える Web 版はありません。学校の時間割との自動連携、通知、単発の振替処理、CSV 取込は初期範囲に含めません。

学校のアカウントは必要になる予定ですか？+

基本機能は登録なしで利用できる設計です。学校の認証システムに依存しないため、学生以外の方にも使えるツールを目指します。現在、Web 版はまだ提供していません。

このプレビューに入力した内容は残りますか？+

残りません。表示切替とチェック操作は、架空のデータを使ったデザイン例です。ここでの操作を保存する機能はありません。将来の端末内保存や JSON バックアップは未実装です。

入力したデータは送信されますか？+

現在、このサイトには日程やタスクの入力・アップロード機能はありません。表示には GitHub Pages への通信があり、ホスティング側で基本的なアクセス情報が記録される場合があります。将来の Web 版も個人データを送信しない設計を基本とします。

九州大学の公式サービスですか？+

いいえ。Cadence は独立したプロジェクトです。大学の公認やシステム接続の許可は取得していません。将来の学校連携は、正式な許可とデータ提供方法の確認が前提です。
